# DESIGN.md 템플릿 — AI 에이전트용 디자인 정본 골격

> **이 파일은 브랜드 캡처가 아니라 템플릿이다.** 컬렉션의 66개 md(9-섹션 브랜드 캡처)와
> next-academy 운영 문서를 전수 평가해 합성하고, service-foundry 7개 spec(문서→토큰→화면)으로
> 실전 검증한 골격 (2026-06).
>
> **사용법**: `[[ ]]` 슬롯만 채우면 새 프로젝트의 design.md가 된다. 골격(섹션·규칙·체크리스트)은
> 미학과 무관하게 유효 — 수정하지 말고, 미학 값만 갈아 끼울 것.
>
> **3대 원칙** (이 템플릿이 존재하는 이유):
> 1. **미학은 1개, 섞지 않는다** — 미학은 배타적. 섞으면 정체성이 죽는다. 컬렉션에서 하나 골라 값을 추출하라.
> 2. **문서는 가르치기가 아니라 분산(variance) 고정 + prior 덮어쓰기** — 에이전트는 좋은 폼을 이미 안다.
>    문서가 할 일은 "매번 다른 그럴듯한 선택"을 하나로 고정하고, 에이전트의 관성(pill CTA·그라디언트·
>    이모지·filler)을 명시적으로 금지하는 것.
> 3. **결정론적 수치만** — "세련되게", "모던하게" 같은 형용사는 0줄. 모든 항목이 grep 가능한 값이거나
>    체크 가능한 규칙이어야 한다.

## 0. Quick Reference

> 에이전트가 전체를 읽지 않아도 이 블록만으로 80%를 커버해야 한다. 화면을 만들 때마다 참조되는
> 사실상의 정본 — 본문과 어긋나면 버그다.

```

  text:    100% primary / 70% secondary / 50% tertiary / 35% disabled
  border:  8% default / 12% strong ([[ring-shadow | CSS border]] 로)
Canvas:    page=[[#______]], 보조면=[[#______]]
Brand:     [[#______]] (기능적 액센트 — CTA·포커스·링크·선택 상태에만)
  hover=[[#______]] / active=[[#______]] / soft bg=[[rgba]]
Tenant/Product 슬롯: --color-tenant ([[사용 | 미사용]])
Status:    success=[[#__]] / warning=[[#__]] / error=[[#__]] (전부 텍스트 AA 4.5:1)
Radius:    input [[_]] / card [[_]] / modal [[_]] / pill [[허용 범위]] — 위계는 의도
Depth:     [[ring + 낮은 그림자 | flat | dramatic]] — 메타포 한 문장: [[____]]
Font:      [[____]]. UI 기본 [[__]]px/[[___]]/LH [[__]]/LS [[__]]
숫자:       tabular-nums 전수 / 통화 풀표기
한글:       word-break: keep-all 전역 (한글 제품이면 필수)
금지:       이모지 / 감탄사 / [[프로젝트 추가 금지 3~5개]]
```

## 1. 토큰 아키텍처

### 1.1 3-tier

```
Primitive(값, 직접 사용 금지) → Semantic(의미, 기본 참조 단위) → Component(컴포넌트 분기)
```

참조 방향 역행·건너뛰기 금지. 하드코딩 hex 금지 (예외: 소셜 로그인 등 외부 브랜드 컬러만).

### 1.2 opacity-driven grayscale — 1번 규칙

회색 hex 를 늘리지 않는다. 회색은 **ink 1개**, 단계는 opacity 로만:

```css
--ink: [[R G B]];   /* RGB 채널로 선언 — rgb(var(--ink) / N) 파생용 */
```

**왜**: 토큰 수가 줄면 AI 가 틀릴 표면이 줄고, 어떤 배경에서도 회색조가 자동 조화된다.
`#8a8a8a` 류 임의 회색이 PR 에 보이면 그것 자체가 위반.

### 1.3 토큰 승격 규칙 (fill-forward) — 미리 완성하지 않는다

```
필요한 값이 토큰에 없다
  ├─ 1. 파생 가능? → 기존 시스템에서 파생 (회색=ink opacity, 간격=그리드 배수, 그림자=보간)
  ├─ 2. 1회성? → 인라인 임의값 허용 — 토큰 만들지 않음
  └─ 3. 2회째 등장 → 승격: ①토큰 코드 추가 ②본 문서 갱신 — ①만 하면 drift 시작
경계: 새 hue = 사용자 승인 필수 / radius 새 단계 = 금지 / 나머지 = 에이전트 재량
```

### 1.4 멀티테넌트/멀티프로덕트 슬롯 (해당 시)

```css
--color-tenant: var(--color-brand);  /* 기본=brand, 런타임 인라인 1줄로 오버라이드 */
```
식별 신호 전용(아바타·인디케이터) — **CTA·포커스·링크 사용 금지** (행동 신호는 항상 brand).

## 3. 타이포그래피

|---|---|---|---|---|

| **body** ⭐ | [[ ]] | | | UI 기본 — 콘솔이면 13~15px 권장 |

## 4. 스페이싱 · 라디우스 · 깊이

- 스페이싱: [[4px]] 그리드. 폼 내부 (라벨↔인풋 / 인풋↔헬퍼 / 필드 간 / 그룹↔CTA) 4값 명시
- 라디우스: **단계별 명시 + 컴포넌트 매핑** (`input [[_]] / card [[_]] / modal [[_]]`) — 단일 변수 금지,
  모두 같으면 위계가 죽는다. pill 허용 범위를 명시 (예: 배지·아바타만)
- 깊이: 메타포 한 문장 → 그것이 모든 그림자 값을 지배. ring-shadow(경계를 border 대신 shadow 로)
  채택 시 layout shift 0 이점 — 예외(테이블 내부 행 구분선)도 명시
- 모션: duration/easing 표 4~6행. [[바운스 허용 여부]] — 콘솔이면 금지 권장
- 접근성 하한: 타깃 ≥[[36/44]]px, 대비 ≥4.5:1, `:focus-visible` 토큰 (outline:none 단독 금지),
  색 단독 의미 전달 금지

## 5. 컴포넌트

> Button / Input / Card / Table / Modal / Toast / Badge — 각각 **수치 표 + 위반하기 쉬운 규칙 1~3줄**.
> 작성 요령: "버튼 만드는 법"이 아니라 "이 시스템의 버튼을 남의 버튼과 구별하는 값"만 적는다.

필수 포함 규칙 (미학 무관):
- Primary 버튼 화면당 1개. Destructive 와 Primary 같은 모달 공존 금지
- placeholder 는 라벨 대체가 아니다 — 라벨 상시 표시
- 테이블: 숫자·날짜 우측 + tnum 필수, 헤더 대문자 변환 금지
- 2단 모달 금지. 닫기는 상단 X 또는 하단 취소 중 하나만
- Toast: 완료 사실만 — 축하·이모지 금지

## 6. 핵심 화면 스펙

> 프로젝트의 첫 구현 대상 화면(보통 auth)을 **구현 기준 수준**으로: 공통 골격 1개 + 화면별 차이만.

```
6.0 공통 골격: 캔버스 [[ ]] + 카드 [[ ]]px (radius·depth·padding) + 제목 스타일
6.1~ 화면별: 필드(타입·autocomplete) / CTA 문구(동사형) / 에러 위치·문구 / 성공 후 이동
```
필수: 로그인 실패는 enumeration-safe ("이메일 또는 비밀번호가...") / 비밀번호 규칙은 사전 고지
(입력 후 깜짝 에러 금지) / 빈·에러 상태 카피까지 명시.

## 7. Anti-AI Guardrails

> **에이전트가 관성적으로 생성하지만 이 시스템에선 위반인 것.** 이 섹션이 템플릿의 심장 —
> "알아서 잘 하는" 그 관성이 정확히 덮어써야 할 대상이다.

| # | 금지 (보편 — 거의 모든 시스템에 유효) |
|---|---|
| 1 | 임의 회색 hex — 회색은 ink opacity 로만 |
| 2 | filler 카드·통계 자동 추가 — 데이터 없으면 비워둠 |
| 3 | 이모지·감탄사 (😊 / 앗! / 환영합니다!) |
| 4 | Primary 버튼 화면당 2개+ |
| 5 | 본문 텍스트에 brand 색 |
| 6 | empty state 일러스트 — 텍스트(+액션)로 충분 |
| 7 | 전체 화면 로딩 — 데이터 영역 Skeleton 만 |

## 8. Audit Checklist — 생성 후 자가검증

> 화면 생성·수정 직후 에이전트가 스스로 점검하고, 위반은 보고 전에 고친다. 가드레일의 실행 장치.

1. **회색 감사** — ink-opacity 외의 회색 hex?
2. **액센트 감사** — brand 가 행동 신호 밖에서? Primary 2개?
3. **경계 감사** — 정본 기법([[ring|border]]) 위반?
4. **라디우스 감사** — 컴포넌트 매핑 위반? 금지 형태(pill 등) 등장?
5. **숫자·한글 감사** — tnum 누락 컬럼? keep-all 누락? 통화 축약?
6. **톤 감사** — 이모지·감탄사·축하·일러스트?
7. **a11y 감사** — icon-only aria-label / DialogTitle / focus-visible 누락? 중복 aria 추가?

## 부록 A — 구현 함정 (실전 검증, service-foundry 2026-06)

문서가 완벽해도 여기서 깨진다. 구현 spec 에 그대로 전달할 것:

1. **Tailwind v4 + 워크스페이스 UI 패키지**: 자동 콘텐츠 감지가 node_modules(pnpm 심링크 포함)를
   스캔하지 않음 → UI 패키지 진입 CSS 에 `@source "./";` 필수. 안 하면 패키지 안에서만 쓰인
   유틸리티(인풋 ring, 버튼 hover)가 통째로 미생성 — "토큰이 절반만 적용된" 화면이 된다.
2. **적용 검증은 클래스명 grep**: `@theme inline` 은 유틸리티에 값을 인라인 — 변수명(`--shadow-ring`)
   grep 은 거짓 음성. `.shadow-ring` 클래스명으로 검증.
3. **`@theme` vs `@theme inline`**: 런타임 오버라이드(테넌트 슬롯·다크모드)는 inline 필수 —
   일반 @theme 은 빌드 시 값이 박제된다.
4. **폰트는 선언만으론 안 로드됨**: `--font-sans` 선언 + 앱에서 webfont 실로드(가변 subset 권장) +
   폴백 체인 첫 항목을 로드되는 폰트명과 일치시킬 것.
5. **a11y 는 "맡기고 빈틈만"**: "접근성 신경 써라" 일반 지시는 무효과 or 과잉 aria 역효과.
   Radix/shadcn 에 위임 선언 + 빈틈 6규칙(icon-only aria-label / DialogTitle / alt / raw input 라벨 /
   focus-visible / 색 단독 금지)만 명문화.
6. **RHF 폼은 `noValidate`**: 네이티브 email 검증이 submit 을 막아 Zod 인라인 에러가 영원히 안 보임
   (jsdom 테스트에서 먼저 드러남). 검증은 Zod 단일화.
7. **shadcn FormMessage 보정**: `role="alert"` 추가 + 에러 텍스트 색은 destructive 가 아니라
   AA 충족 error-text 토큰.

## 부록 B — 동반 문서 구성 (권장)

```
docs/design/DESIGN.md        ← 본 템플릿의 인스턴스 (정본)
docs/design/TOKEN.md         ← CSS 변수 ↔ 프레임워크(shadcn 등) 매핑 + 승격 규칙
docs/frontend/FRONT.md       ← 범용 스택 패턴집 (프로젝트 간 이식용)

```
분리 기준: 범용(이식) vs 특화(이 레포). "왜"는 ADR 로, 문서엔 "무엇·어떻게"만.
